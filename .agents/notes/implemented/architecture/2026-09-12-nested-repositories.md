# Agent Note: 一个项目里的多个仓库：仓库列表与「Root」选择器

Status: implemented

日期：2026-09-12
范围：`local.pi-idea-git` 的 `main.js`（`refreshWorkspace` / `selectedRoot` /
`scanNestedRepositories` / `submodulePaths` / `discoverRepositories` /
`readRepo` / `readDiff` / `workspaceRelativeRoot` / `git/{repos,select-repo}`）
与 `src/common.js`（`mountRepoSelector`、i18n）、`src/commit-view.js`、
`src/git-view.js`、`tools/harness.mjs`、`tools/smoke.mjs`

## 问题

用户报告："当前这个插件无法识别在一个仓库下面的子模块仓库。"

实测（`$PI_SCRATCH_DIR/repro`：外层仓库 + 真子模块 `mod` + 未声明的嵌套仓库
`nested`，桩 `pi` 驱动真引擎）复现出三个各自独立的问题：

1. **真子模块只能看到一行 `mod`**。`git status --porcelain=v2` 给的是
   `1 .M S.M. 160000 … mod`，插件解析成 `submodule: true, insideSubmodule: true`，
   于是列表里是一行带「子模块」徽标的条目，它的 tooltip 写着"请先在子模块里提交"
   —— 而工具窗口里根本没有任何地方能提交子模块里的东西。
2. **未声明的嵌套仓库完全不可见**。`git status` 只给一行 `? nested/`
   （即使 `-uall` 也不进去，因为那是个仓库），里面已提交、未提交的改动一律看不到；
   `git add` 它只会记一个 gitlink，还附带 Git 的 embedded repository 警告。
3. **`git/repo` 恒返回工作区所属的那个仓库**，所以 `log` / `branches` / `stash` /
   `commit` 全部只作用于外层仓库：子模块的历史、分支、储藏一行也读不到。

结论：不是"识别得不够好"，是**引擎只有一个仓库的概念**。子模块与嵌套仓库是
独立的 Git 仓库（父仓库只记录子模块指向哪个提交），任何一条命令都作用不到它们内部。

## 决策

### 1. 单一咽喉：让 `readRepo()` 决定用哪个仓库

用户选定的形态是 IDEA 的 **Root 下拉**：两个工具窗口顶部一个仓库选择器，
选中后整个窗口切到那个仓库。实现上没有把「当前仓库」串进 41 个命令，
而是让 `readRepo()` 返回被选中的仓库 —— 因为**审计后确认全部 41 处 `runGit`
调用里只有 `readRepo()` 自己是默认 cwd，其余 40 处都显式 `cwd: repo.root`**。

这一点是这次改动能小到可控的原因：`git status` / `diff` / `log` / `stash` /
`commit` / `apply --cached` 全都通过 `withRepo()` 或 `repo.root` 拿工作目录，
重定向一个函数就等于重定向整张命令表。父仓库侧的行为（`mod` 那一行）完全不变。

### 2. 选择属于「打开的那个项目」，不跨项目存活

`selectedRoot` 是模块级状态，插件进程却跨项目切换存活。所以
`refreshWorkspace()` 在**发现工作区变化时清除选择**（保留原先的"不缓存工作区路径"约定），
`readRepo()` 每次还会验证选择仍然是一个仓库根、且仍在这个工作区里（子模块可以被
deinit，目录可以被删），失败就静默回退到工作区仓库 —— 回退比报错更接近用户预期。

选择是**会话级**的，不写入 `git/prefs`：下次打开同一个项目时，用户期望看到的是
项目自己的仓库，而不是上次随手点过的某个子模块。

### 3. 发现：边界写在明处，声明优先于猜测

`git/repos` 用一次有界遍历（`REPO_SCAN_DEPTH = 4`、`REPO_SCAN_BUDGET = 5000`
个目录、`REPO_SCAN_SKIP` 依赖/构建/缓存树）找出所有目录里带 `.git` 的仓库；
**发现一个仓库不会停下遍历**，否则"子模块的子模块"永远列不出来 —— 而列表永远是
从工作区仓库算起的，恰恰是用户抱怨的同一类场景。

`.gitmodules` 声明的路径**不受上述任何边界限制**：声明是项目关于自己的陈述，
边界只是我们对项目大小的猜测。反过来说，声明了但没 checkout 的路径不列
（没有工作树可以看、可以提交）。

`kind` 由**持有它的那个仓库的 index** 判定，而不是 `.gitmodules`：父仓库把子模块
记成一条 `160000` gitlink，暂存/提交作用的就是这条 entry；没有这条 entry 的嵌套
仓库只是"恰好住在里面"（父仓库不保存它的任何文件）。判定按持有者分组，每组一条
`git ls-files --stage -z -- <paths…>`，成本不随嵌套仓库数量增长。

遍历会下钻到仓库内部，所以 `rel` 是相对**工作区仓库**的路径（`mod`、`a/b/mod`），
这也正好是选择器显示的名字：只显示 basename 时，用户分不清选的是哪个 `mod`。

### 4. 切仓库要丢掉仓库相关的状态

文件选择、改动过滤词、已渲染的 diff、改动文件列表、分支/路径过滤、打开的
commit diff 浮层，全都是**仓库相对**的。视图在 `refresh()` 里记住上次加载的
仓库根（`loadedRepo`），一旦变化就清掉这些，而不是让它们描述上一个仓库。
提交信息框**不清**：那是用户敲过的字，静默删掉比留在那里更糟。

## 一次独立复核逼出的三个真问题（同批修掉）

实现完成后交给独立只读复核（`reviewer` 子代理，结论 `concerns`），暴露出三个
必须修的。它们都不是"风格问题"，而是能摸到用户文件或指向错文件的：

1. **`workspacePrefix` 不能把 `null` 折成 `"."`**。当仓库在工作区**之上**
   （工作区本身是仓库的子目录）时前缀无意义，折成 `"."` 会让"打开文件"去要
   `app/app/f.txt`（把仓库相对路径又拼到工作区上），或更糟——切到兄弟仓库后指向
   工作区里同名的另一个文件，而改动前这里是禁用状态。现在 null 原样传到视图，
   由视图的回退分支处理。（harness 第 13 节固化。）
2. **切仓库期间旧 diff 仍然可点**。`git/select-repo` 立即改状态，而视图要等一次
   刷新（实测 50–200ms，大项目更久）才重绘；这期间残留的「Discard Hunk」按钮按
   `git apply -R` **写工作树**，会落到新仓库里。两道防线：
   - 视图在 `onSwitch` 里**先**清状态再 reload，不再只依赖刷新后的对比；
   - 引擎侧为 `git/apply-patch` 增加 `root` 校验：补丁带不回它的来源仓库就拒绝
     （`code: "STALE_REPOSITORY"`），视图回传 `state.diff.root`。
3. **子模块的子模块被判成 `nested`**。对持有者提问时，pathspec 必须是持有者的
   相对路径（`mod/dep` 对 `mod` 是 `dep`），查出的记录也要把持有者前缀拼回去；
   原实现两条都漏，于是这类子模块永远分类错误。

复核另外指出的小问题一并处理：仓库列表**不再随每次刷新重扫**（改在挂载、项目
切换、以及打开下拉时读）；`.gitmodules` 不存在时不 spawn `git config`；
`ls-files --error-unmatch` 探针走新增的 `quiet` 选项，避免正常路径在 Console 里
显示成失败。

## 顺手修掉的两个既有缺陷（它们不属于这个功能）

两个都是**改动之前就错**、但这次切仓库让它变得可达或更显眼的东西：

- `readDiff` 的「未跟踪文件」兜底此前用"`git diff` 输出为空 + 文件存在"判定，
  而**干净且已跟踪**的文件同样满足这两条 ⇒ 选中它会渲染成整文件新增。现在先问
  `git ls-files --error-unmatch`（与 `git/discard` 同一判据）。harness 第 14 节固化。
- `workspaceRelative()`（打开文件 / 在访达中显示）用两个绝对路径字符串比较
  `repo.root` 与 `workspace`。Git 给的是真实路径（macOS 上是 `/private/var/…`），
  宿主给的是用户打开时的路径（`/var/…`），于是同一个目录被判成"在仓库外面"，
  两项操作被静默禁用。现在由引擎算好 `workspacePrefix`（按真实路径比较）。

## 已知近似

- 深度 4 以上、或因跳过清单而未遍历到的嵌套仓库不会出现在列表里 —— 除非
  `.gitmodules` 声明了它。跳过清单是依赖/构建/缓存树（`node_modules`、`vendor`、
  `Pods` 等），里面出现仓库通常是被 vendor 进来的副本。（harness 第 12 节把这条
  行为固化成断言。）
- 符号链接目录不参与遍历（`Dirent.isDirectory()` 对符号链接为 false）。指向别处的
  链接仓库不会被列出，好处是环状链接不可能被跟随。
- 仓库列表按工作区仓库为根生成，所以选中一个嵌套仓库后再打开列表，看到的仍是
  同一份列表（不会以子模块为根重新扫一遍）。
- `kind` 只区分 `root` / `submodule` / `nested`；子模块是否已初始化不单独表示
  （未初始化的不列）。

## Alternatives considered

1. **只在改动列表里分组显示嵌套仓库的改动**（不切换仓库）。否决：父仓库根本无法
   暂存/提交子模块内部的东西，分组只能展示、不能操作，等于把"看不见"换成"看得见但
   点不动"；而且子模块的历史、分支、储藏仍然读不到。
2. **每个仓库一个视图/标签页**。否决：两个 docked view 是宿主固定的两个入口，
   没有动态开视图的通道（`.memories/pi-desktop-plugin-runtime.md`），
   一个下拉比一堆标签更接近 IDEA，也不改动视图数量。
3. **把「当前仓库」作为参数串进每个通道**。否决：41 处调用点等价于 41 次改动、
   41 次漏改机会；`readRepo()` 单点重定向已被审计证明足够。
4. **用 `git status --porcelain` 的输出反推嵌套仓库**（`? dir/`、`160000` 条目）。
   否决：只认得"脏的"或"已记进 index 的"仓库，一个干净的嵌套 clone 完全看不见；
   而且反推不出未跟踪目录**内部**的仓库。
5. **无界递归遍历**。否决：刷新时跑在一个大小未知的项目上；`node_modules` 一个
   目录就能让工具窗口卡住。边界 + 「声明优先」是权衡后的取舍，代价写在 README 里。
6. **持久化选择**（写进 `git/prefs`）。否决：见决策 2，跨会话记住一个子模块
   会让"打开项目"和"看到项目"对不上。
7. **给子模块一行加「在子模块里打开」的上下文菜单**，而不是顶部选择器。
   否决：用户明确要的是 Root 下拉；而且入口只出现在"父仓库恰好把它当子模块记着"
   的行上，未声明的嵌套仓库（`? nested/`）根本没有这样一行可点。

## 后果

- **收益**：子模块与未声明的嵌套仓库都进列表、都能整体切换（`log` / `branches` /
  `stash` / `commit` 作用于该仓库），父仓库侧 `mod` 那一行的行为不变。
- **收益**：改动小到可控 —— 审计确认 41 处 `runGit` 里只有 `readRepo()` 是默认 cwd，
  其余 40 处都显式 `cwd: repo.root`，重定向这一个函数就等于重定向整张命令表。
- **收益**：刷新不被发现成本拖住 —— 仓库列表改在挂载、项目切换、打开下拉时读，一次
  刷新是 0 次 `git/repos`；深度/预算/跳过清单把遍历锁在有界范围内。
- **收益**：切仓库期间不再改错文件 —— `onSwitch` 先清状态再 reload，`git/apply-patch`
  校验补丁来源（`code: "STALE_REPOSITORY"`），`workspacePrefix` 为 `null` 时原样传到
  视图，不再折成 `"."` 指向工作区里的同名文件。
- **收益**：两个既有缺陷随批落地 —— `readDiff` 未跟踪兜底改用
  `git ls-files --error-unmatch`（干净且已跟踪的文件不再渲染成整文件新增），
  `workspaceRelative()` 按真实路径比较，「打开文件 / 在访达中显示」不再被静默禁用。
- **收益**：选择器显示相对**工作区仓库**的路径（`mod`、`a/b/mod`）而非 basename，
  同名 `mod` 可区分；符号链接不参与遍历，环状链接不可能被跟随。
- **代价**：发现边界是猜测 —— 深度 4 以上、跳过清单内、符号链接目录里的仓库都不列（除非
  `.gitmodules` 声明）；列表恒以工作区仓库为根，`kind` 只有三态、未初始化子模块不列。
- **代价**：选择不跨会话存活 —— 不写 `git/prefs`，工作区变化即清除，失效时静默回退（比报错
  更贴近用户预期，但不告知用户）；提交信息框切仓库不清，静默删掉用户敲过的字比留着更糟。
- **代价**：风险是真实的 —— 独立只读复核（`reviewer` 子代理，结论 `concerns`）在实现
  完成后仍挖出三个会摸到用户文件或指向错文件的真问题，已修并有 harness 断言覆盖。
