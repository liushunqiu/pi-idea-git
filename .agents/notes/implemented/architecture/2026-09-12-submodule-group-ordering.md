# Agent Note: Commit 视图按 IDEA 排序：大类 → 仓库行 → 文件

Status: implemented

日期：2026-09-12
范围：`src/commit-view.js`（`paintChanges` 改为大类→仓库两级分组、
`repoRow`/`repoColorMap`/`applyInclusionForRepos`/`repoContextMenu`）、
`src/theme.css`（`.repo-row` / `.repo-color`）、前篇聚合笔记的后续

## 问题

前一篇（`2026-09-12-submodule-aggregation.md`）的聚合是"父仓分组在上、
子模块各一节在下"，用户对照 IDEA 截图指出排序展示不一样。IDEA 的结构是
两级：先按"更改 / 未进行版本管理的文件"分大类，大类下按**仓库**排，
每个仓库一行"颜色块 + 复选框 + 名 + N 个文件 + 分支徽标"，父仓
（`haeco-mes-parent`）按字母序排在子模块中间，文件再嵌在仓库行之下。
旧实现有三处对不上：父仓没有仓库行；暂存/未暂存各出现一套仓库节；
同屏仓库颜色是纯哈希，5 个仓撞 8 色的概率不可忽略。

## 决策

### 1. 大类 → 仓库行 → 文件树，父仓参与字母排序

`paintChanges` 改为：对每个大类（冲突/已暂存/未暂存/未跟踪保持不变，
checkbox 语义仍是 index）收集"有可见文件"的仓库桶（父仓 + 脏子模块），
桶按仓库显示名（父仓用 `repositoryLabel()`，即名或相对路径）字母序排，
每个桶先渲染仓库行、再渲染它的文件树（树/平铺模式照旧，嵌套深度 +1）。
单仓项目（无脏子模块）**完全不变**，不渲染任何仓库行——这是用
`multi` 开关显式保证的，渲染测试 S2 固化。

### 2. 仓库行 = disclosure + 级联复选框 + 颜色块 + 名 + "N 个文件" + 分支徽标

"N 个文件"复用 `t("files")`（en "5 files" / zh "5 个文件"，与 IDEA 文案一致，
不新增 i18n）；分支徽标复用 `.badge`；颜色块是新 `.repo-color` 方块。
右键菜单只留"切换到该仓库"（行上不再放切换按钮——之前每组一个会重复）；
父仓行右键无菜单（只 `preventDefault`，避免冒出原生菜单）。

### 3. 同屏颜色去重：排序后线性探测

`repoColorMap(allCtxs())` 每次绘制从排序后的仓库集合分配：起点是 rk 哈希，
撞色就往后探。仓库集合不变则颜色稳定；同屏内保证不重色。跨大类复用同一
map，所以 backend 在"未暂存"和"未跟踪"里是同一个颜色（渲染测试断言）。

### 4. 大类复选框跨仓批量，一次刷新

`applyInclusionForRepos(buckets, next)`：每仓一次 `git/stage|unstage`
（带 `repoRoot`），`Promise.all` 后只 `refresh()` 一次，再走与单仓路径
相同的 gitlink 提示。仓库行复选框仍走单仓 `applyInclusion`。

### 5. 附带修：批量函数解构了不存在的字段

`applyInclusionForRepos` 初版把桶解构成 `{ files, ctx }`，而桶的字段叫
`visible`——大类复选框一点就 `TypeError`。是渲染测试 S1 的交互断言抓到的
（纯语法检查和只读渲染都发现不了），修为 `{ visible, ctx }`。

## Alternatives considered

1. **把已暂存/未暂存合并成一个"更改"大类**（与截图字面一致）。否决：那会动
   checkbox = index 的语义（本插件立身之本），用户要的是"排序"不是改语义。
2. **仓库行只排子模块、父仓永远置顶**。否决：用户明确要 IDEA 的字母序，
   父仓排第三（backend/frontend/**haeco-mes-parent**/prototype-design/works）
   正是截图的样子。
3. **颜色按序号分配（第几个仓用第几个色）**。否决：仓库变干净/变脏会让别的
   仓变色；哈希起点 + 同屏探测兼顾稳定与去重。
4. **把"未纳入版本控制的文件"改名为 IDEA 的"未进行版本管理的文件"**。
   暂不动：超出"排序"范围，无谓的文案 churn，且旧文案已被用户习惯。
5. **仓库行保留"切换到该仓库"按钮**。否决：同一仓库在大类下出现多次时按钮
   重复，噪音大；切换入口收敛到右键菜单 + 左上选择器。

## 后果

- **收益**：默认视图与截图同构——大类 → 颜色块仓库行（含父仓，字母序，
  同屏不重色）→ 文件树；单仓项目零变化。
- **收益**：交互测试证明大类/仓库两级复选框的跨仓扇出正确（每仓一次调用、
  `repoRoot` 与 paths 对应），这是纯渲染检查覆盖不到的。
- **代价**：折叠键格式再变（`group:<id>` / `repo:<group>:<rk>`，内存态，
  无迁移问题）；`REPO_COLORS` 8 色、集合变化时后来者的颜色可漂移。
- **代价**：冲突组的仓库行无复选框（13px 占位保持对齐）；父仓行右键无菜单。
- **风险**：`repoRow` 的颜色来自调用方传入的 `colorMap`，漏传时回退灰色
  `#888888`——目前唯一的调用方每次都传，防御分支只为将来。
