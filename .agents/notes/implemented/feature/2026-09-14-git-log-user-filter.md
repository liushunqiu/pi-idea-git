# Agent Note: 日志提交者过滤支持指定人（对标 IDEA）

Status: implemented

## 问题

工具栏的提交者过滤只有两档：全部 / 只看我的（截图现状）。仓库稍大就有多个提交者，
用户要看指定人的提交时无处可选，只能回到终端 `git log --author`。

## 决策

抄 IDEA 的三段式菜单，后端只加一个正交只读通道、老通道签名不动：

- 引擎（`main.js`）：新增 `git/authors`（`readAuthors`），用
  `git log --all --max-count=2000 --pretty=format:%an%x1f%ae` 聚合近 2000 条提交，
  按提交数倒序取前 N（默认 30），返回 `{ name, email, count }`。具名过滤复用
  `git/log` 现有的 `--author` 参数，名字或邮箱都可（Git 自身按两者匹配）。
- 视图（`src/git-view.js`）：`userFilter` 从 `"" | "me"` 扩展为 `"" | "me" | 具名`；
  菜单为 全部 / 只看我的 / 最近提交者（名字 + 提交数 + `name <email>` 悬停）/
  手输框（回车即滤，名单之外的人也能滤）；当前手输值不在名单里时单独给一行带勾，
  避免“选了却看不见选中态”。按钮文案显示名字本身，过长 240px 截断；“只看我的”
  悬停显示解析出的 `user.name`。
- 切仓时具名作者清空（仓相关），`"me"` 保留（按新仓 `user.name` 重解析）。

## 验证

- `node --check` 三文件过；`node tools/harness.mjs` 208/208（新增 2 条：名单含提交者且带数、limit 生效）。
- `node tools/build.mjs` 产物含新文案与菜单逻辑；`git/authors` 在空仓库返回空名单，
  菜单退化为 全部 / 只看我的 + 手输，不报错。

## Alternatives considered

- `git shortlog -sne --all` 取名单：走全历史，大仓库慢且不可限条；`log --max-count`
  封顶 2000 条，名单只是选择器不是人口普查，名单之外靠手输补，否决 shortlog。
- 按 `name <email>` 组合键区分同名不同邮箱：同名极少，合并展示、取首个邮箱；
  真遇到时手输邮箱仍可精确过滤，加键的复杂度不值，否决。
- `--author` 包 `^…$` 做精确匹配：名字含正则字符要转义，且子串匹配在实践中更符合
  “找这个人”的预期（与既有 "me" 路径行为一致），保持原样，否决。
- 输入框输入时实时重建菜单做名单过滤：重建会丢输入焦点，要额外做焦点恢复；
  菜单本就不长（20 行），手输回车直滤已覆盖，否决。

## 后果

- 收益：指定人的提交在窗口内可滤，名字/邮箱都行；名单按提交数排序，常用的人在上面。
- 代价：点开菜单多一次 capped 的 `git log`（约百毫秒级）；`userFilter` 状态从二值变三值，
  后续动过滤逻辑要记得具名分支；`main.js` 通道表 +1。
